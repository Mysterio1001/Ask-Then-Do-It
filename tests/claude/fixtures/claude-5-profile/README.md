# Claude 5 static contract fixtures

`source-contract.json` is a fixed, complete source reference for the ten prompt
modules. It is never regenerated by tests, derived from a mutation candidate, or
updated on failure. Review its complete diff with each intentional prompt change.
The comparison normalizes CRLF to LF only; indentation, case, ordering, comments,
fences, final newlines, and appended instructions remain significant. Every
scenario checks all ten candidate sources, including modules outside its nominal
ownership. The references in this correction await independent Review.

`scenarios.json` contains all 30 specified scenario IDs and 66 structured reference
cases. Each records given capability, public-entry route, state and user decision,
then expected module load, transition, artifact, status, disclosures and forbidden
actions. These are authored reference observations for human review and later
model runs. They are not fed to a pretend Claude simulator. Tests validate their
structure and exact scenario/module mapping and check complete prompt integrity;
they do not claim the inputs caused those observations in Claude.

`decisions.json` independently specifies 65 cases with 71 table-selection steps.
Only these steps execute a deterministic representation: a test-only selector
reads the four closed Markdown tables in the supplied orchestration source and
returns the first matching decision. Every input key/value is checked against a
closed schema. Higher-priority rows intentionally make some fields immaterial
(e.g. direct diagnosis does not depend on delivery approval). Each step consumes
its complete own input. Status-then-changed-state sequences evaluate both the
status row and the later fresh-state row; they do not simulate a host state store.
The selector never runs the named command, loads a Claude module, persists an
artifact, infers a model response, or turns reference text into observed evidence.

Mutation checks exercise both full-source integrity and, separately, independent
table expectations. The Core trace check fixes every module's exact rule
occurrences, including intentional duplicates, rather than checking only a union.

Passing this suite establishes static instruction integrity and closed table
selection. It does not establish the Specification's mandatory live-model
behavior, paired equivalence, authenticated host semantics, or Ticket completion.
Tickets 3/6 and final live smoke retain their required evidence gates.
