- `confirmed`: The Claude 5 Skill will use substantially less context and progressive disclosure, while both Claude variants preserve the same workflow semantics and important approval, safety, evidence, and artifact boundaries.

- `confirmed`: `1.4.0` will deliver a native Claude Code Plugin containing the general and Claude 5-optimized Skills, state-aware CLI/Marketplace installation and update guidance, a version-matched manual ZIP fallback, and complete conformance/eval/release validation.
- `confirmed`: `1.4.0` will add Claude explicitly to the current release pipeline and defer a universal Adapter Registry.
- `confirmed`: The supported Claude distribution uses the official Claude Code Plugin and Marketplace mechanism, and users accept Plugin-namespaced Skill commands.
- `confirmed`: `/ask-then-do-it:ask-then-do-it` will be the primary convenience entry and will use Plugin-level, best-effort model routing rather than asking a Skill to self-identify its active model.
- `confirmed`: The Plugin router will use officially documented model signals, including the optional `SessionStart.model` value and `PostModelSwitch.to_model` on Claude Code `2.1.251` or later, with routing state isolated by Claude session under the Plugin's persistent data directory.
- `confirmed`: The instruction profile is bound when a public Ask Then Do It command starts an operation and does not change midway through that operation. `PostModelSwitch` records the newly active model and informs the user that the current operation retains its original profile; the next invocation of a public Ask Then Do It command applies routing from the updated model state. This avoids mixing the general and Claude 5-optimized instruction sets within one requirements, specification, planning, implementation, or review flow.
- `confirmed`: When the router identifies a Claude 5-generation model, it selects the Claude 5-optimized profile; when it identifies another Claude model, it selects the general Claude profile.
- `confirmed`: When the active model cannot be identified reliably, routing fails safe to the general Claude profile and tells the user that compatibility mode was selected; it must not guess that the model is Claude 5.
- `confirmed`: `/ask-then-do-it:ask-then-do-it-5` remains available as the explicit manual entry for the Claude 5-optimized profile.
- `confirmed`: Automatic routing is a best-effort convenience, not a claim of perfect model detection. Claude Code Skills expose no `${CLAUDE_MODEL}` substitution or model-conditional loading contract, and Skill frontmatter `model` selects or overrides a model rather than detecting it.
- `confirmed`: Both Claude profiles inherit the user's active Claude Code model. Neither Skill pins, overrides, or switches the model; Plugin routing changes only the instruction profile.
- `confirmed`: Invoking `/ask-then-do-it:ask-then-do-it-5` never switches models. When routing state confirms Claude 5 or cannot identify the model, the explicit command selects the Claude 5-optimized instructions.
- `confirmed`: If routing state positively identifies a non-Claude-5 model when `/ask-then-do-it:ask-then-do-it-5` is invoked, the Plugin tells the user that the profile is incompatible and safely continues with the general Claude profile instead of running the reduced-context profile.
- `confirmed`: The `1.4.0` manual ZIP fallback contains the same complete Claude Code Plugin used by Marketplace installation, including its manifest, router, hooks, both model profiles, documentation, and Plugin-namespaced commands.
- `confirmed`: The Marketplace-installed Plugin runtime payload and manual ZIP Plugin runtime payload derive from one canonical Claude Plugin source and must preserve equivalent runtime behavior, runtime content, and validated inventory. The expanded release package and its ZIP must be byte-equivalent; deterministic release-only legal files may be added under the existing builder policy without treating the Marketplace catalog itself as package content.
- `confirmed`: `1.4.0` does not provide a second fallback that extracts the profiles into `~/.claude/skills` as personal Skills. Claude Code versions without the required Plugin mechanism are outside the supported compatibility range.
- `confirmed`: The supported model baseline for the Claude Adapter is Claude 4.6 or later. Claude models earlier than 4.6 are outside the formal support and conformance matrix.
- `confirmed`: When trustworthy routing state positively identifies Claude 4.5 or an earlier model, Ask Then Do It must stop before starting an operation and tell the user to select Claude 4.6 or later. It must not silently continue under the general profile. Only genuinely unknown model state uses the already approved general compatibility mode; a positively identified unsupported model is not treated as unknown.
- `confirmed`: Supported Claude 4.6-generation models use the general Claude profile, while supported Claude 5-generation models use the Claude 5-optimized profile when routing can identify them.
- `confirmed`: The minimum supported Claude Code software version is `2.1.251`, independent of the Claude model baseline. This version is required for the approved `PostModelSwitch`-based tracking contract.
- `confirmed`: Installation, update, and runtime guidance must detect a Claude Code version below `2.1.251`, stop supported activation, and tell the user to upgrade. `1.4.0` does not maintain a degraded old-Claude-Code routing mode.
- `confirmed`: Release `1.4.0` keeps one lockstep identity across Core, Codex, Generic, the Claude Adapter and Plugin, current documentation, generated packages, checksums, conformance declarations, and release evidence even when Codex and Generic behavior is unchanged.
