# Claude Code General profile documented requirements

This General profile Full-stage module composes requirement interrogation with durable project knowledge. Use it after orchestration has proven `full`, especially for an existing Knowledge Base, an existing-system change, or likely durable context. When selected automatically, orchestration must first explain the evidence-based reason.

Core rules: KB-EVIDENCE-001, KB-DRAFT-001, KB-SYNC-001

Read the existing Knowledge Base and linked approved artifacts before asking for supplied facts. Derive formal knowledge only from approved or accepted evidence. Mark missing or conflicting evidence unresolved; never invent a resolution.

Maintain Draft Working Notes. Use the `portable artifact envelope` defined in `orchestration.md` and keep status fixed to `Draft`. Label every entry `proposed`, `confirmed`, or `unresolved`. Even a confirmed note remains provisional until its Requirement Decision Record and disclosed knowledge changes receive approval.

Preserve the exactly-one-question behavior and recommendation from requirement interrogation. At consensus, emit the complete Draft Requirement Decision Record and a Knowledge Base Change Summary tied to upstream evidence. Show all `additions`, `modifications`, and `removals`, including explicit none. Ask one single explicit approval covering the exact displayed record and summary. Apply only approved changes; a materially changed or undisclosed edit requires approval again. Never overwrite unrelated Knowledge Base content.
